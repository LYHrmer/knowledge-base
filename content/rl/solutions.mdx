## 第 1 课：MDP 与 RL 五要素

**Q1：为什么 γ 不能等于 1？**
答：当 episode 是无穷长的、reward 不是终会为 0 时，$G_t = \sum_{k=0}^\infty r_{t+k}$ 可能发散到无穷，期望无意义。γ < 1 让几何级数收敛，使所有价值都是有限值。短任务（episode 必终止且 reward 终会 0）允许 γ=1，但通常不这么做。

**Q2：撞墙改 reward = -100，最优策略变吗？**
答：不变（仍然往右），但 Q 值会变小（撞墙的状态 Q 更负）。最优策略是 argmax Q，加个固定的"惩罚"对所有动作 Q 的相对差不影响。γ 没出现在答案里是因为 reward 平移不影响 argmax。

**Q3：V 和 Q 哪个更细粒度？为什么算法都学 Q？**
答：Q 更细。V(s) 只告诉你"在 s 总体能赚多少"，Q(s,a) 进一步告诉你"在 s 选具体动作 a 能赚多少"。RL 要做决策（选 a），所以 Q 更直接。给定 Q，π* = argmax_a Q(s,a)；只给 V，要从 V 推 π 还得知道 P 和 R。

**Q4：Bellman 为什么叫"递归"？联系动态规划。**
答：V(s) 用 V(s') 定义，s' 又用 s'' 定义……这是函数自指。动态规划（DP）正是"把大问题拆成小问题，子问题答案重复利用"的方法。Bellman 是 DP 之父，他研究控制论时把这个思想形式化。Q-learning / DQN 都是 DP 在 RL 里的样本版本。

**Q5（开放）：开车北京到上海建 MDP，三种 R 设计。**
提示维度：
- 极简 R：只有到达 +100，其余 0（解干净但难学）
- 时间敏感 R：每小时 -1 + 到达 +100（鼓励快）
- 多目标 R：油耗 / 安全 / 时间 加权（最现实但最难调）
评分维度：能不能学出来 / 是否会"reward hacking"（比如时间惩罚 → 学会 200km/h）/ 工程可调性

## 第 2 课：Q-learning + 表格法

**Q1：ε 不能一直 1.0 也不能 0？**
答：ε=1.0 永远随机，永远学不到具体动作的 Q（因为不在乎 Q 选谁）。ε=0 一开始 Q 全是 0 时随机选一个最早走通的路径就死锁，永远不试别的。需要先大后小。

**Q2：α=1.0 和 α=0.001？**
α=1.0：$Q \leftarrow R + \gamma \max Q'$，完全用最新一次的样本覆盖，**忘了历史**，方差极大。α=0.001：每次只朝目标移 1‰，**几乎不学**，要 1000 倍以上 episodes 才收敛。

**Q3：γ 从 0.9 改 0.5，最优策略变吗？最优 Q 变吗？**
最优策略不变（仍直走到糖果），但最优 Q 值显著变小（远期奖励折得更狠）。Q*(0,右)：γ=0.9 时 ≈ 6.56，γ=0.5 时 ≈ 0.625。

**Q4：去掉步数惩罚，能学最优策略吗？**
能学到一个能拿糖果的策略，但不一定是"最快"那条。比如先撞墙再走和直接走，G 都是 10 × γ^(到达步数)，γ 仍能压死绕路。但如果 γ=1，所有能到糖果的策略 reward 都一样，最优变成"任意能到糖果的策略"。

**Q5（开放）：5×5 grid 火坑 + 糖果**
提示：n_states = 25, n_actions = 4。reward 设计：糖果 +10、火坑 -10、撞墙 0、普通 -1。Q 表 (25, 4)。最优策略应该绕开火坑走右下。验证：画一个 5×5 网格 print(np.argmax(Q, axis=1).reshape(5,5))。

## 第 3 课：DQN

**Q1：为什么 Replay Buffer 要随机采样而不是按顺序？**
答：连续 transition 高度相关（s' 就是下一时刻 s），相关样本让梯度估计有偏 + 高方差。随机采样近似 IID 样本，符合 SGD 假设。

**Q2：硬同步 vs 软更新（τ）本质等价吗？**
近似等价但平滑度不同。硬同步每 N 步一次大跳；软更新每步小幅 EMA。数学上软更新等价于"指数加权平均的硬同步"。τ=0.005 大约对应每 200 步硬同步一次，但更平滑。SAC 偏爱软更新，DQN 历史上偏硬，现在两者都常见。

**Q3：Double DQN 的核心？**
Q 估值有噪声 → max 算子选"运气好被高估的"动作 → 系统性正向偏差。Double DQN：用 在线网络选动作（argmax），用 target 网络评估它的 Q。**分开就把"选偏"和"估偏"解耦**，偏差消除一大半。

**Q4：环境非平稳，Replay Buffer 会带来什么问题？**
老数据基于旧的 reward / dynamics 收集，已经过时。算法用旧数据更新，会"学回去"。解法：减小 buffer 容量 / 给新数据更高优先级 / 动态重置 buffer。

**Q5（开放）：6 关节每关节 5 档，5^6=15625 个动作直接 DQN 行吗？**
提示：DQN 输出层有 15625 个 head，参数和计算 O(K^n) 爆炸；探索更难（ε-greedy 1/15625 概率试某个）；Q 函数光滑性差（相邻动作语义不连续）。
解法：拆分式 Q（每关节独立 Q，假设动作可分）/ 转连续动作用 SAC 等 / 用层次 RL（先选关节再选档）。

## 第 4 课：REINFORCE

**Q1：为什么是 log π 而不是 π？**
log 把"概率乘积"变"概率加和"（轨迹概率展开），求梯度时只关心策略部分（动力学项无 θ → 求梯度 0）。同时 log 让梯度对小概率事件更敏感，不会被大概率主导。本质上 log-derivative trick：$\nabla \pi = \pi \nabla \log \pi$。

**Q2：returns 都加 100 / 减 100 会怎样？**
理论上不变期望梯度（baseline 不变期望），实际上**方差变化**。加大常数会让 advantage 始终为正，每个动作概率都被推高（互相竞争 softmax 仍能学），训练慢；减常数对应：advantage 大多为负，所有动作概率都被推低（不可能，softmax 归一化），效果是相对差不变，**类似一个隐式 baseline**。

**Q3：log_std 初始化太大 / 太小？**
太大（比如 2.0，对应 std=7.4）：动作几乎纯噪声，根本学不到方向。
太小（比如 -3，对应 std=0.05）：策略几乎确定，探索为 0，陷局部最优。
经验起点：log_std = 0（std=1），训练中网络自动调节。

**Q4：REINFORCE 比 DQN 抖很多为什么？**
REINFORCE 是 Monte Carlo 估计，单条轨迹噪声极大；DQN 用 buffer + bootstrap，每个 batch 平均了大量样本。
解法：A2C 加 baseline 降方差，PPO 加 clip 稳定。

**Q5（开放）：7 自由度机械臂学画圆，REINFORCE 不会成功的两条理由。**
提示：
- 高维连续动作空间，单条轨迹方差爆炸，需百万级 episodes
- 没有 critic，每一步都要等到 episode 结束才算 G_t，长 episode 信用分配难
- 无 buffer 重用，sample 效率太低
其他：reward 设计难（什么叫"圆"？误差量化）

## 第 5 课：A2C

**Q1：advantage 为什么 detach？**
advantage 给 actor 当"权重"用，actor 通过 log π × advantage 求梯度。如果不 detach，梯度会从 advantage 流回 critic（critic 会被 actor 损失"拉"，目标错乱），导致 critic 学到的不是 V 而是奇怪的东西。

**Q2：critic loss 用 returns 还是 TD error？**
都行但形式不同：
- returns：$L = (V - G_t)^2$，Monte Carlo 目标，无偏但高方差
- TD error：$L = (V - r - \gamma V')^2$，bootstrap，低方差但有偏
A2C 经典实现用 returns + bootstrap 的混合（n-step return）。两者期望一致，方差/偏差权衡不同。

**Q3：entropy 系数 0 / 0.1 / 0.01？**
0：策略迅速塌缩到 deterministic，常陷局部最优
0.1：探索过强，CartPole 上策略接近随机
0.01：经典平衡值，多数任务好用
任务越复杂、动作空间越大越需要高一些。

**Q4：完全分开 actor / critic 不共享 backbone？**
优点：互不干扰，调试容易
缺点：参数翻倍，两个网络看同样 obs 学两套表征浪费
实际：小任务分开，大任务共享 backbone。还有 layer-normalize 防止互相干扰的折中方案。

**Q5（开放）：A2C 比 REINFORCE 方差小，但训练时间为何可能更长？**
提示：A2C 多了 critic 网络要训，每 step 算两个梯度 + 共享 backbone 反向传播两次。reward 收敛步数少，但单步更慢。在简单任务（CartPole）总时长可能反而长，复杂任务才扭转。本质是"为更稳的梯度付出计算代价"。

## 第 6 课：PPO

**Q1：为什么 PPO 要 importance sampling 而 A2C 不要？**
A2C 是 on-policy，每收集一批立刻更新一次然后丢。PPO 想**多次复用同一批数据**（n_epochs=10），但策略更新后旧数据是 π_old 采的，不是当前 π_θ 的，需要 importance ratio 修正。

**Q2：clip 的 min 不取行不行？**
不行，会出现"clip 反向激励"。
当 A>0 时，r 太大被 clip 到 1+ε（梯度 0，OK）
当 `A<0` 时，r 太小被 clip 到 1-ε（梯度 0，OK）
但反过来：`A<0` 且 r 比 1+ε 大时，**不取 min 你会优化让这个动作概率上升**（错误激励）。`min(r·A, clip·A)` 保证只在让目标变小时 clip 生效。

**Q3：GAE 的 λ 和 γ 区别？**
γ 是 reward 折扣，由 MDP 定义（任务侧），影响最优策略。
λ 是 advantage 估计的 bias-variance 平衡，由算法定义（学习侧），不影响最优策略。
λ=0 → 纯 1-step（高 bias 低 variance），λ=1 → 纯 Monte Carlo（低 bias 高 variance）。0.95 是甜蜜点。

**Q4：PPO 是 on-policy 还是 off-policy？**
on-policy（严格说是"近 on-policy"）。clip 的存在保证了策略不会偏 π_old 太远，所以重用数据仍能近似 on-policy。如果不 clip 就是真 off-policy 但不稳。

**Q5（开放）：n_steps=2048 在焊接任务对应多少秒？影响训练效率？**
提示：焊接控制频率假设 50Hz（dt=20ms），2048 步 ≈ 41 秒。一个 episode 100 步（2 秒），2048 步约 20 个 episode。
影响：n_steps 太短覆盖样本少，梯度估计差；n_steps 太长收集慢，更新频率低。机器人任务 n_steps 一般 1024-4096 是合理范围。

## 第 7 课：自定义 Gym 环境

**Q1：为什么 obs 要用 sin/cos 而不是 θ？**
θ 在 -π 和 π 之间跳变是同一个物理位置，但数值差 2π。神经网络看到这种"一个量突变了 2π"完全乱套。sin/cos 让 -π 和 π 数值一致（都是 sin=0, cos=-1），网络看到的是连续输入。

**Q2：稀疏 reward 加什么辅助？**
- 进度奖励 / shaping reward
- 课程学习（先简单任务再难）
- HER（Hindsight Experience Replay）
- 模仿学习先 warm-start

**Q3：GAE 计算时 terminated / truncated 区别？**
terminated（任务真结束）：V(s_T+1) = 0，TD error = r - V(s_T)
truncated（时间到了，物理还在继续）：V(s_T+1) ≠ 0，TD error = r + γV(s_T+1) - V(s_T)
代码里：`(1 - done)` 这个 done 应该只是 terminated，不包括 truncated。否则会错误地把"时间到"也当成"结束了，没下一步价值"。

**Q4：action 不归一化训练曲线？**
训练曲线会呈现"前期完全乱、后期慢慢学"。原因：神经网络输出在初始化时大致是 N(0, 1) 量级，物理量可能是 [-2, 2]（力矩）甚至 [-100, 100]（电压）。前期 actor 输出几乎全在 ±2σ 范围，远远不够覆盖最优 action 范围。归一化让 [-1, 1] 网络输出对应 [-max, max]，从 episode 1 就能探索全空间。

**Q5（开放）：SeamTracking 三种 obs/action/reward 设计**
版本 A（state-based）：obs = 关节角 + 末端 + 焊缝偏移，action = 末端速度 6D，reward = -offset + progress
版本 B（vision）：obs = 图像 + 末端，action 同 A，reward 同
版本 C（end-to-end）：obs = 图像，action = 关节速度 6D，reward 同
对比维度：训练数据需求 / 泛化能力 / sim2real 难度 / 部署计算量。

## 第 8 课：Domain Randomization + ROS2

**Q1：DR 类比数据增强？**
完全一样。监督学习数据增强（旋转 / 裁剪 / 噪声）让模型对图像变换鲁棒；DR 让策略对物理参数变化鲁棒。本质是**让训练分布覆盖测试分布的"领域宽度"**。

**Q2：无法仿真的扰动（焊弧随机）怎么办？**
- 收集真机数据训"扰动模型"，再加进仿真（system identification）
- 在策略输入加随机扰动 / dropout（让策略对感知不全鲁棒）
- 混合训练：仿真 + 部分真机微调
- 后处理：策略输出后加滤波 / smoothing 抹掉高频噪声

**Q3：观测顺序错了的怪现象？**
策略行为时对时错（错的程度依赖错位维度的物理量）。比如把 "关节1位置" 和 "关节2位置" 调换：策略输出可能像"在对的状态下做相反的事"，但 reward 曲线可能慢慢爬坡（神经网络能强行学合错的映射），最终性能比正常差 30-50%。**极难发现**，因为不会直接报错。
解法：obs 拼接的代码集中到一个函数，env 和部署都调用它（DRY 原则）。

**Q4：TorchScript vs ONNX + TensorRT？**
TorchScript：PyTorch 原生，部署简单，CPU/GPU 都行。适合：原型 / 频率不严苛。
ONNX + TensorRT：跨框架 + GPU 高度优化（量化、kernel 融合），延迟低 5-10 倍。适合：高频实时（如 200Hz 视觉策略）。
工作量：TorchScript 30 分钟，ONNX+TRT 一天起。

**Q5（开放）：5 / 10 / 20kg 负载机械臂统一策略**
DR 设计：质量 [5, 20] kg，惯量按质量 scale，关节摩擦 ±30%，电机最大力矩匹配真实分级。
关键：obs 里加"当前负载估计"（让策略能 condition），不加就会学到"中性策略"性能受限。
进阶：privileged learning，仿真给 GT 负载，部署用估计器。

## 第 9 课：LQR / MPC

**Q1：在工作点附近线性化用 LQR，何时失败？**
失败条件：
- 实际状态偏离工作点过远（线性近似误差大）
- 系统强非线性（如机械臂大角度，sin θ 不能再 ≈ θ）
- 系统经过 "fold"（雅可比奇异）
- 控制量饱和（LQR 不知道约束）

**Q2：MPC 的 horizon N 太大太小？**
小（N=5）：近视，错过远期最优。
大（N=200）：每步求解开销大、不可行约束概率高。
联系 GAE：N 类似 GAE 的 step 数。短=低方差高偏差，长=高方差低偏差。

**Q3：焊接视觉对线为何不适合 LQR？**
状态不是低维向量而是高维图像，无法写出线性 dynamics。reward 也很难二次形式。LQR 假设的两个前提全破。

**Q4：PPO 训不出但 LQR 能解的简单任务？**
线性 cartpole 平衡（不要去倒立 swing-up）。LQR 立刻给出最优 K 矩阵，PPO 要训几万步才接近。
更好例子：直流电机精确控制，已知电气模型 + 简单代价函数，LQR 直接计算，PPO 浪费时间。

**Q5（开放）：用 MPC 当 BC expert？**
好处：
- MPC 不需要人示教（自动产生大量"专家"数据）
- 可以 randomize 物理参数让 MPC 在不同条件下产数据，扩大 BC 训练分布
- BC 学到 MPC 的近似但比 MPC 推理快（神经网络毫秒级 vs MPC 毫秒-几十毫秒）
风险：MPC 自身的次优会被 BC 继承，所以 expert 质量是上限。

## 第 10 课：SAC

**Q1：SAC 的最大熵 vs PPO 的 entropy bonus？**
SAC：把 α H(π) 加进 reward 本身，相当于"长期"目标里有熵
PPO：entropy 只在当前 actor loss 加项，不进 V/Q，是"瞬时"鼓励
结果：SAC 的最优策略本身就是 stochastic 的（熵正则解），PPO 的 entropy bonus 是训练辅助，最终策略可以是 deterministic。

**Q2：为什么 SAC 需要 twin Q 而 DQN 不需要？**
DQN 的 max 在动作集合上离散 argmax，过估计有但还能容忍。SAC 是连续动作，actor 对 Q 求梯度，**Q 高估的方向直接被 actor 顺着学**，正反馈崩盘比 DQN 严重得多。Twin Q + min 取最坏估计，pessimism 防崩。TD3 同理。

**Q3：不重参数化（用 score function）？**
score function 估计是有效但方差大很多（REINFORCE 那种）。重参数化把"对随机变量的期望梯度"变成"对确定函数的梯度"，方差小一两个数量级。SAC 训不动几乎都是因为没用 rsample。

**Q4：off-policy 但 actor 用当前策略采样，矛盾吗？**
不矛盾。off-policy 指的是"训练数据来自旧策略 / 任意策略"。actor loss 计算时**用 buffer 里的状态 s**，但**动作 a 是当前策略对 s 重新采样的**——这只是为了估 actor 对 Q 的梯度，不是 sample 来自 buffer 的旧 (s,a)。

**Q5（开放）：SAC vs PPO 焊接 sim2real？**
PPO 优势：对 randomization 友好（on-policy 不会"利用"buffer 里旧分布的捷径），更稳。
SAC 优势：样本效率高（重要！如果你的仿真昂贵或想真机微调）。
权衡建议：从 SAC 出发，仿真效率高，**真机部署前用 PPO 在 randomized env 重新训一遍**当 robust 化。或者直接 PPO + 大量 randomization。

## 第 11 课：BC + DAgger

**Q1：BC 在 SL 看完美却部署崩？画状态分布。**
专家轨迹是个细窄分布 P_expert(s)。BC 学到的策略部署后，**自己生成的状态分布 P_policy(s)** 与 P_expert 不一样。一旦稍微偏离 → BC 在新状态上没见过 → 输出乱 → 状态偏更远。误差按时间二次累积。

```
P_expert(s):    ▁▁▂▆▇▆▂▁▁
P_policy(s):    ▁▃▅▇▆▄▃▂▂  (偏宽 + 漂移)
```

**Q2：用 MPC 当 DAgger 专家行不行？**
完全可行。MPC 在策略遇到的状态上能算出最优 u，作为标签返还。优点：自动 + 大规模。缺点：MPC 自身次优会传给 BC（同 L9 Q5）。还有：MPC 在线计算，DAgger 整体训练也变慢。

**Q3：BC 用 MSE 不够什么时候？**
1. 多模态动作（L13 讲）：MSE 学到峰值平均，错。
2. 离散动作：用 cross-entropy 而非 MSE。
3. 需要不确定度：预测高斯分布并最大化 likelihood。
4. 高维输出：MSE 各维独立，丢失结构（如序列）。

**Q4：专家不完美会怎样？**
BC 学到"专家平均水平"，**包括他们的错误**。如果错误多样化（不同人不同错），BC 学到混合，可能比单个专家差（往中间塌）。如果错误一致（系统性偏差），BC 完美继承这个偏差。
解法：预过滤数据（剔除明显失败 / 取性能 top X%）/ RL 微调让真实 reward 修正。

**Q5（开放）：100 条焊接示教，BC+RL 还是从零 PPO？**
判断维度：
1. 仿真精度：高 → PPO 可行；低 → BC 更稳
2. reward 写起来难度：难 → BC 优先
3. 100 条示教质量：高且多样 → BC 强基线；同质 → BC 泛化差
4. 时间预算：3 周 → BC 快；3 月 → PPO 可
通常 100 条示教 + BC + RL fine-tune 综合最好。

## 第 12 课：焊接端到端实战

**Q1：v1→v2 关键修复？**
进度奖励（r_progress = 100 × Δprogress）。少了它，agent 学到"停在原地，offset 不变"是次优解。
本质：reward 必须包含"前进"信号，否则长任务退化为"原地最优"。

**Q2：r_progress 系数？**
- 1：太弱，被 r_offset 主导，类似 v1 退化
- 1000：进度太强，agent 不修偏，飙过去拿完成奖励
- 100：平衡，前进 + 修偏

**Q3：焊缝是曲线，env 怎么改？**
1. seam_dir 改成局部切向量（沿曲线变化）
2. progress 改成沿曲线弧长（不是 x 坐标）
3. offset 改成"垂直当前切向的距离"
4. obs 加局部曲率信息

**Q4：真机限速 30% 除安全外的 RL 角度？**
1. 训练时控制频率 50Hz、命令幅度某范围。真机限速 30% 让真实控制留在训练分布内（一种 conservative deploy）
2. 留时间观察 + e-stop
3. 出现意外低速可恢复，高速可能损伤

**Q5（开放）：1 周计划 100 条录像 → 上线 RL seam tracking。**
提示骨架：
- Day 1-2：数据预处理 + state/action 提取标准化
- Day 3：BC baseline，仿真验证
- Day 4：PPO + BC warm-start，仿真训练 + DR
- Day 5：仿真测试 + sim2real gap 分析
- Day 6：真机重力补偿模式 + 低速度试验
- Day 7：调优 + 部署文档
关键：每天有可量化 milestone（reward 数值、成功率），不是模糊的"调一调"。

## 第 13 课：Diffusion Policy

**Q1：为什么高斯学不到多模态？画 -log p。**
目标分布双峰：p = 0.5 N(-1, 0.1) + 0.5 N(1, 0.1)。
高斯拟合的最优解是均值 0、方差大（覆盖两峰）。
-log p(a|s) 在 a=0 处反而最低（高斯峰值），但**真实分布 p(a|s) 在 a=0 处接近 0**！高斯永远学不到。

**Q2：α / β 是什么？画 ᾱ_t 随 t 变化图。**
β_t：每步加多少噪声（小）
α_t = 1 - β_t：每步保留多少
ᾱ_t = α_1 × α_2 × ... × α_t：t 步后保留多少原信号
图：ᾱ_t 从 1 单调递减到接近 0（典型 100 步从 1 到 1e-4）。这表示"t 大时几乎全是噪声了"。

**Q3：DDIM 跳步效果还行的原因？**
diffusion 的 reverse process 可以等价看作 ODE 的离散化。DDIM 用 ODE 视角的"高阶积分"跳步，类似 Euler 改 Runge-Kutta。100 步 → 10 步精度差不多，但需要"非随机"的 deterministic sampling。

**Q4：chunk=1 / chunk=100？**
chunk=1：每步一个 sample，等价于"per-step diffusion"，受当前观测主导，抖动严重，不利于规划性任务。
chunk=100：1 秒规划（50Hz），策略更"全局"，但难纠错（中途偏了要等 100 步才重新规划）。
经验值 chunk=8-16 + receding horizon（每次只执行前 8 步，再重新预测）。

**Q5（开放）：焊接是单峰任务，Diffusion 还有优势吗？**
单峰场景下高斯 BC 也行，Diffusion 工程复杂度反而是负担。
但有些"准多模态"场景：
- 跳过铆钉时绕左还是绕右（双峰）
- 起焊位置上 / 下 偏置（人示教时多种习惯）
- 多种工艺参数对应不同动作分布
有这些，Diffusion 价值显现。否则 BC + 高斯 / 离散够用。

## 第 14 课：World Models / Dreamer

**Q1：World Model 学不准会怎样？**
策略在"梦"里训练，被 world model 的偏差主导。常见模式：
- WM 漏了某个动力学约束（如关节限位），策略学到"穿越限位"的捷径
- WM 短期准长期发散，策略对长期规划过度自信
- WM 有偏差但稳定，策略学到一个"对该 WM 是最优"但部署崩
解法：经常用真实环境校准 WM 的预测误差，作为停训信号。

**Q2：为什么 Dreamer 用离散 latent？**
1. 高维连续 latent 容易"信息泄漏"（z 编码 obs 太多细节，KL 难以学好）
2. 离散 latent 更接近"概念"（如 "墙" "球"），泛化更好
3. 训练更稳定（V2 论文实测）
代价：离散 sample 不可微（用 straight-through estimator 解决）。

**Q3：KL(post || prior) vs KL(prior || post) 在 Dreamer。**
post：见 obs 后的判断
prior：没见 obs 的预测
通常用 KL(post || prior)，让 prior 接近 post。
Dreamer V2 用 **KL balancing**：分别用两个权重对应两种 KL 的混合，让两者训练速度匹配（避免一方主导导致 representation 塌缩）。

**Q4：Reward predictor 错了，如何发现？**
WM 内 imagine rollout 的累积 reward 远高于真实环境同策略的 reward → reward predictor 高估。
监控：每过 N 步，比较"梦里 reward 平均" vs "真环境 reward 平均"，差超过阈值告警。

**Q5（开放）：用 Dreamer 训焊接最大难点？**
- 视觉 + 物理 + 焊接电弧多模态融合，WM 要 model 这一切
- 长任务（焊一段 vs 跳过铆钉），imagination 长度可能不够
- 训练复杂度极高，团队需有 ML 工程师维护 Dreamer 代码
- 仿真到真机的 WM 都要重新校准

## 第 15 课：VLA

**Q1：亚毫米精度焊接，离散 token vs flow matching？**
离散 token：256 bin × 0.5m 工作空间 ≈ 2mm 精度，亚毫米不够。
flow matching：连续输出，精度由网络容量决定，亚毫米可达。
焊接选 flow matching（π₀ 路线）。或者：离散 token 输出粗规划 + 局部精细修正（hierarchical）。

**Q2：100 条示教，LoRA OpenVLA vs ResNet BC？**
判断维度：
- 数据多样性：高（多种焊缝类型）→ OpenVLA 大模型先验有用
- 泛化要求：要 zero-shot 新工件 → OpenVLA
- 推理频率：≥30Hz → ResNet BC
- 算力：单卡 24GB 行 → 都行；嵌入式 → ResNet BC

**Q3：焊接指令对 VLA 是挑战的原因？**
VLA 训练数据（Open X-Embodiment）是"日常物体操作"语料，"焊接 T 字接头到 3mm 余高、电流 180A" 这种**专业术语 + 数值参数**几乎没在训练里出现，语义先验失效。
解法：用焊接领域语料 LoRA 微调指令理解层。

**Q4：Hierarchical VLA 优劣？**
优势：
- 高层 VLA 慢推理（5Hz）+ 低层 PPO 快控制（100Hz），分离时间尺度
- 安全边界清晰（低层不会输出离谱命令）
- 模块独立可替换
劣势：
- 接口设计困难（"VLA 输出什么给低层"）
- 端到端优化丢失（高低层不联合学）
- 工程量大

**Q5（开放）：1 周 VLA 数据采集计划。**
提示：
- Day 1：定 schema：图像 + 关节状态 + 焊接电流 + 语言指令模板
- Day 2-4：采集 200-500 条不同工件 / 焊缝类型，每条配语言指令
- Day 5：标注审核（语言准确性 + 动作完整性）
- Day 6：归一化 + 分 train/val
- Day 7：跑通 OpenVLA 推理 baseline + 简单 LoRA 试运行
关键：先**少量高质量**（100 条精标）跑通流程，再扩。

## 第 16 课：RLHF & 机器人对齐

**Q1：sigmoid 而不是 softmax？**
偏好对**只有两条**轨迹。两类用 sigmoid，多类用 softmax。Bradley-Terry 模型本质是"两两比较"，sigmoid 天然合适。如果做 K 路对比（A>B>C），可以扩展到 Plackett-Luce 模型 + softmax。

**Q2：β 太大太小？联系 SAC α。**
β 大：策略动不了（KL 限太严），效果差。
β 小：reward hacking 风险大（自由偏移）。
和 SAC α 类似：α 大鼓励熵 / 探索过头；α 小压缩到 deterministic 易陷局部。
都是"约束 vs 自由"的 trade-off 系数。差别：SAC α 是熵正则，RLHF β 是分布距离正则。

**Q3：DPO 等价于隐式 RM + PPO 的条件？**
DPO 损失推导自 "RM + KL 约束 PPO" 的最优解析解。等价条件：
- π_SFT 是 reference policy
- KL 约束系数为 β
- RM 由数据集隐式定义（即 r_φ(s,a) = β log[π*(a|s) / π_SFT(a|s)] + 常数）
所以 DPO = "假设我们能闭式解 RLHF 的目标"。

**Q4：偏好不一致怎么处理？三种方案。**
- A. 多数投票：3 人选 2 个 A，定为 A。简单但丢信息。
- B. 软标签：A 偏好概率 = 票数 / 总数，loss 用软交叉熵。
- C. 多 RM：不同人/维度训各自 RM，最后加权或集成。
推荐 C 用于多维度场景，A 用于一致性高场景。

**Q5（开放）：1 页"焊接 RLHF 标注指南"。**
提示骨架：
- 维度：飞溅、平滑度、速度、咬边
- 单一维度评分尺度（1-5 或 -2 到 +2）
- 综合判断："看 4 个维度，加权选更好的"
- 何时跳过：两条都太差 / 维度互斥矛盾
- 操作：先看完整再选，不被前几秒主导
- 校准：每天前 5 对让多人标，对比偏差
